** networking (its own)
- a cache on disk (RFC 9111): an answer its server lets be used again
  is kept (Cache-Control's max-age and immutable, Expires; not
  no-store, not one that varies by a request header), given back
  without a request while it is fresh, asked about after
  (If-None-Match, If-Modified-Since; a 304: the copy, renewed).
  Http_cache has the rules, Browser_cache the files: one a copy in
  ~/.cache/mini-chrome, 200 MB at most, the least recently used
  going first; read and written on the pool's threads. Reload asks
  the network; cache=off, profile=off: none; about:cache lists them.
  GitHub's page the second time: 138 of its 160 answers from the
  disk, its files' list 5 s sooner
- a body in Brotli or Zstandard is read (Content-Encoding: br, zstd;
  tiny_libs' Brotli, with its dictionary, and Zstd, elm-playground
  after 0.3.3), and asked for: Accept-Encoding: gzip, br, zstd.
  Berkshire Hathaway, which answers in Brotli whatever is asked, loads
- cookies (RFC 6265): a response's Set-Cookie kept (Domain, Path,
  Expires and Max-Age, Secure, HttpOnly), said back in the Cookie
  header of the requests to its site, a redirection's before the next
  request (a sign-in); one jar for the browser, shared by the
  requests on threads (Cookie, Cookie_jar); document.cookie for the
  page's scripts; those with a date kept between runs in the
  profile's Cookies file (Browser_cookies), not with profile=off;
  about:cookies shows the jar. Not done: the Public Suffix List,
  SameSite
- libs/network: elm-playground's networking, the part a browser needs
  (Url, Urlencoded, Http; Asn1, Pem, X509, Tls13; Tcp, Worker,
  Tls_client, Http_client, Http_request), copied to grow here (cookies,
  compression, keep-alive); the cryptography stays tiny_libs'.
  Wrapped (the Playground links tiny_libs' modules of the same names)
  but opened by the libraries using it: the code says Http_request,
  not Network.Http_request
- src/chrome/Fetch: the requests in flight, after the Playground's
  native Commands.ml: http:// by Http_request stepped each frame,
  https:// by Http_client on Worker's threads (threads=off: the frame
  waits); a tab asks for a fetch by a message and never touches a
  socket, the program steps them on each Tick. The Playground no
  longer fetches anything for the browser
- gzip: "Accept-Encoding: gzip" sent, a body with "Content-Encoding:
  gzip" decompressed (Http.parse_response, over tiny_libs' Gzip, in
  elm-playground after 0.3.3): Wikipedia's article on OCaml comes as
  64 KB instead of 354
- tests/network, tests/network_unix: 49 tests (RFC 3986's table, RFC
  8448's TLS 1.3 trace, real certificate chains, a GET over localhost)

** tools
- the browsers before this one, from elm-playground, on the browser's
  own libraries (Fetch and our TLS for their requests, the same tab):
  mini-mosaic (NCSA Mosaic, 1993: the grey window, the globe, the
  stages of the pipeline as views), mini-netscape (1994-1997: its

  firefox; tools/platform, the window they are linked with;
  scripts/tools/dump_old_browsers.sh dumps their pages
- scripts/js/Page_scripts.exe: a saved page's scripts run with no
  window, their console, requests and cookies said, a question asked
  of the page at the end
- mini-node: the JavaScript engine in a terminal, as Node.js is V8 in
  one (tools/node: Node_host, MiniNode). A file run as a module, -e a
  text, or a console; console, process (argv, env, exit, stdout),
  timers on the machine's clock and the loop that waits for them,
  require with CommonJS modules (a file run once, in a function that
  gives it exports, require and module), fs (readFileSync,
  writeFileSync, existsSync). Js_eval.eval_in_run and call_in_run: a
  host function called by a script running a text or a function
- mini-curl (tools/curl): a URL fetched and printed by the browser's

- mini-httpd (tools/httpd): a directory's files served on 127.0.0.1
  (-p port): a file's type from its extension, a directory's

- mini-lynx (tools/lynx): a page (an address or a file) as text, its
  links numbered; a number typed follows one, an address opens it, b
  comes back (-dump: no prompt; -w: the width). Line_mode: div,
  section, form, table and a table's row are lines of their own
- tests/tools, an eighth suite: the tools' worked examples, mini-curl
  and mini-lynx on mini-httpd's server forked on a temporary
  directory; Node_host's tests moved there
- docs/sites.md: sixteen sites, from the first web page to BBC News,
  and what each lacks by part (network, HTML, CSS, text, JavaScript),
  in colours; twelve real scripts the same way. 8 sites green, 4

- make loc, make loc-v (scripts/stats/loc.py, after elm-playground's):

- scripts/js/Js_survey.exe: real scripts parsed and run, the first

** speed
- styles kept from one styling of a page to the next (Cascade's
  memo, Computed's on top). A page whose scripts change its tree is
  styled again whole, and nearly all of it is as it was: each element
  now has a key -- two hashes of all a selector can read of it: its
  name and attributes, whether it is empty, the siblings before it,
  whether it is the last, and the same of every ancestor -- and what
  the rules gave for a key is found again without a rule tried; the
  style computed from the very declarations under the very parent's
  style likewise. The simple way stays (opti=off), and a test styles
  a page ten times changed both ways. Numbers in
  docs/plans/plan_performance.md
- a long string made by + is a rope (Js_value's Rope: the two pieces,
  written out when first read): a text grown a character at a time
  was copied whole at each addition -- 200,000 additions, 34 s; now
  0.3 s. A rope lives in a script's variables only: a property, an
  array's item, an argument of a function of ours are given the
  String. YouTube's scripts replayed: 29 s to 22
- YouTube's search, first results after 15 s where it was 19, all of
  them after 41 where it was 49 (OCaml 5.5.1). Sampled (gdb started
  with the program and interrupted four times a second: half the
  samples in the collector), then counted: querySelectorAll("*") was
  asked 5,285 times, each a copy of the tree it searches -- 6.4
  million elements -- mostly by our own registry of custom elements;
  it is now the elements under it, nothing copied. And a script that
  is not a module is parsed where it was fetched, as modules were
  (Js_eval.read_ahead): 3.2 s of the window's thread to 0.8. Found
  and left: strings built a character at a time by the site's
  anti-robot code (100,000 appends, 1.5 GB copied: a seventh of the
  scripts' time, and a rope's worth of change to the engine)
- OCaml 5: the pool's workers are domains (Worker_spawn, chosen by
  dune on the compiler's version; threads under 4.14, the same
  source), so fetching, TLS, decompression and pictures' decoding run
  beside the window on other cores. GitHub's page with its scripts,
  to its last picture: 25 s with 4.14, 12 s with 5.5.1 (58 s before
  this day's work). Eight workers, were six threads
- the wheel scrolls the page while a script runs, not at its end
- a module's text is read (parsed) by the job that fetched it, on the
  pool: GitHub's 119 modules, 1.3 s that the window's thread no
  longer spends under OCaml 5; timings=on has a "parse" line
- a picture is decoded on the thread of the pool that fetched it, not
  in a frame (GitHub's README: 4.5 s of the window's thread)
- one layout a frame: a picture come, a tree a script changed mark
  the tab, laid out once at the next frame, not at each (GitHub with
  its scripts: 39 layouts in a load to 24)
- timings=on: where the time went, by stage (html, sheets, styles,
  boxes, shapes, scripts, pictures, view, update), each with how many
  times and its own seconds, said when the program ends (Stopwatch:
  named spans that nest, a span's own time its time less its
  children's)
- a page's styles, three times cheaper on a big sheet (GitHub's 1,823
  elements and 25,273 rules: a pass 3.0 G instructions to 1.3; with
  its scripts on, 39 passes, 25 s to 6): a class looked for in the
  attribute's text and not in a list of its words; rules with no id,
  class or name in their last part filed under an attribute's name or
  what a :where() holds, not tried on every element; an element's
  declarations in a table; an attribute found by a string's equality;
  an element filed under its name and attributes, not all it holds
- JavaScript, three cheap things the big engines do (plan_js_speed.md
  has the table of what they do and what of it is cheap here):
  an object of many properties has a table beside its list
  (Js_value.find, "dictionary mode": a prototype of thirty methods was
  a list walked at each call; a loop of method calls 5.0 G
  instructions to 3.5 G); a module's text is parsed once, not once to
  list its imports and again to run; the collector has more room
  before a major pass (space_overhead 200). Discourse's start, counted
  by callgrind: 65 G instructions to 44 G
- array.push and pop work at the array's end (each made the whole
  array again: a list built by pushes cost its length squared)
- matches, closest and querySelector freeze what a selector reads --
  the element, its ancestors and their children, or the element
  searched -- not the document; a selector's text is read once
  (Script_dom.select_opti, matches_opti; opti=off: the whole tree).
  A click on a Discourse topic: 38 s of script to about 10
- Discourse's start, the scripts alone: 56 s to 17 (docs/dev/
  notes_debugging_techniques.txt, session 5). None of it the
  interpreter's own speed: Map, Set and WeakMap hashed; an element's
  and an attribute's origin (Dtd) asked once, not at each freeze of
  the tree; querySelector freezing the tree once, not each element
  with all it holds; the lexer comparing a punctuation in place, by
  its first character; the parser's operators' table. The page in the
  browser: 53 s to 38 to its last picture
- a page with hundreds of custom properties (--x) and megabytes of
  sheets is styled three times faster (Discourse's: 571 ms to 195): a
  name's last declaration found without a list gone through for each
  (Cascade), the custom properties in a map (Computed.Custom), the
  index of the rules kept between two runs with the same sheets
- discuss.ocaml.org's front page: 29.5 s to its last picture, now 7.5
  (docs/dev/notes_debugging_techniques.txt, session 5). Three things:
  a page is laid out once when the last of its style sheets has come,
  not at each (31 sheets, a second each: the cascade over 1.2 MB of
  CSS); an https:// connection is kept for the next request to its
  host (Keep_alive: 150 requests were 150 TLS handshakes, 0.2 s of
  arithmetic each; opti=off closes each as before); six threads fetch,
  a browser's six connections a host, where four did
- JavaScript, the compiled bodies again (docs/plans/plan_js_speed.md):
  what a frame of the Playground's menu asks was counted, and each
  answered where it is asked, in Js_compile -- the function's own
  names and the ones around's read by their slot with no call, no
  scope for a body that declares nothing (an if without braces, a
  switch, a try), typeof x, instanceof and a regexp's text no longer
  the evaluator's, the common operators each their own closure, true
  and false made once, an array's item and length at once, a built-in
  method found once at the place that calls it, a small call frame
  written out, an integer written as text without printf; the lexer's
  keywords in a table. A menu frame 172 ms to 130 (773 million
  instructions to 553), its start 1.7 s to 1.3, a loop 640 ms to 515.
  Node with its compiler off is three to five times faster still
- JavaScript: a function's body compiled to closures at its first call
  (Js_compile: an expression a function of its scope, made once from
  those of its parts; SICP's "analyze", Feeley and Lapalme's closure
  generation), apart from the evaluator, which it calls for what it
  does not compile (classes, patterns, spreads, with, labels) and
  which knows it by one reference; js=walk, and Js_bench's
  compile=off, keep the evaluator. A quarter on a real program (the
  Playground's menu: 195 ms a frame to 172), 1.6 times on a loop: what
  is left is what a tree and its closures share (a frame a call, a
  list of arguments, a value a number). A call makes its arguments
  array only if the function says arguments. tests/js three times:
  compiled, walked, opti=off
- an Ogg file's sound (Vorbis, Opus) decoded as it plays, three
  seconds ahead of the player, not whole when it is opened
  (Sound_stream: the samples there at once, silent, filled from the
  front; the rate changed sample by sample, with no seam): a song of
  four minutes no longer makes its page wait a quarter of a minute.
  Not a WebM's sound yet, and nothing is forgotten once played
- the JavaScript engine about four times faster
  (docs/plans/plan_tinybox.md; scripts/perf/Js_bench.exe: a loop of 3M
  turns 5.9 s to 1.0, 1M calls 3.7 s to 0.67, the Playground's menu
  compiled by js_of_ocaml 6.8 s to start and 870 ms a frame, now 2.0 s
  and 206 ms). Two thirds of the time was in the scopes' tables: a
  scope is now an array of bindings and each name in the program's
  text remembers where it was found, how many scopes up and which slot
  (Js_scope: an inline cache; a call's frame made at once from its
  function's layout, Js_frame.opti). The parser's tree stays as
  written: the places are in a copy of it made before it runs, a Name
  there a Local, a var's names a Var_set, a function with its layout
  (Js_quicken: the JVM's and CPython's word). The simple way is kept
  beside it (tables, a name hashed in each scope: opti=off), and
  tests/js is run on both. Also: two numbers added with no conversion
  (Js_operators.arithmetic_opti), an array's item by its number and
  not by a string (Js_eval.item_opti), an object's keys compared as
  strings, no scope for a block that declares nothing, strict mode a
  flag of the scope and not three names looked up at each call
- libs/opti: Mini_opti.enabled, the switch between an optimized
  function and the simple one kept runnable beside it (after
  elm-playground's Opti); opti=off on the command line, and on
  scripts/perf/Page_bench.exe's. Nothing checks it yet
  (docs/plans/plan_performance.md, step 1)
- a line's shapes built when it is first shown, not the whole page's
  at each relayout (Browser_draw.later, between; opti=off: as before).
  Wikipedia's article on OCaml, 16,000 pixels high: a relayout 450 ms
  to 28, the page first shown in 239 ms instead of 796, its load

- a letter drawn as one picture made once (Glyph_picture: its opacity

  instead of 74 (Cairo), 32 instead of 116 (software), and a scroll

- a Wikipedia article scrolled: a step from 340 ms to 15. Cairo's

** Features
- helper applications, as Mosaic had (Browser_helpers): programs of
  the person's, written in the profile's Preferences ("helpers"),
  given what the browser does not show. A rule for a site
  ({"site": "youtube.com/watch", "run": ["mpv", "%u"]}) adds "Open
  with mpv" to the right click's menu, on the page and on a link to
  it: a YouTube video plays in mpv's window. A rule for a content
  type ({"type": "application/postscript", "run": ["gv", "%f"]}) has
  such a page written to a file and the program run on it, the tab
  saying so. Only a program named there is run (Cap.exec), each
  argument its own, started without a fork (OCaml 5's domains) and
  not waited for. mini-httpd says a .ps file is PostScript. One rule
  needs no writing: a YouTube video's address to mpv, when mpv is
  installed; the profile's rules come before it
- A custom element is told of an attribute it observes set or
  removed later (attributeChangedCallback, from setAttribute and
  removeAttribute; not inside a <template>'s content, which a browser
  keeps in a document of its own). YouTube starts a video's page by
  removing disable-upgrade from its application: the page now builds
  -- the player's frame and controls, the related videos with their
  thumbnails -- and says, in YouTube's words, that this browser
  cannot play the video (no MediaSource; the plain file it then asks
  for is refused, 403, to any asker)
- YouTube's icons: an inline <svg>'s height in percents is of its
  block's (it was 0: every icon a flat line); a path's arc may have
  its two flags glued to what follows ("a9 9 0 105.6 16", a
  minifier's: the magnifier was a blot); and a property a script put
  on an element before its class was defined is its own
  (hasOwnProperty says so, it comes before the class's accessor, and
  delete takes it away): what Polymer looks for at an element's
  upgrade to take the values its parent gave it early -- the
  masthead's icons had lost theirs
- YouTube's search page whole: its twenty results, the views and
  ages, the channels' pictures, the filter chosen; the lower ones'
  thumbnails come as the page is scrolled. MutationObserver is told
  of a text node changed (data/prelude/web.js; the browser calls
  __mutated): the trick by which Polymer runs its every debounced job
  "right after this script", and Vue 2 where it finds no promise --
  ours was told nothing, and none ran. IntersectionObserver looks at
  where an element is (in view within a window's height; looked at
  again twice a second while some wait): all was said to be in view,
  and a list that asks for its next page when its end is seen grew
  without end. A page's scripts know how far the window has scrolled
  (scrollY, and getBoundingClientRect is from the window's top)
- YouTube's search page looks like YouTube's: each result with its
  thumbnail and its length, the playlists and the shelf of Shorts
  among them, two minutes after it is asked. Five things, none
  YouTube's alone: a boolean and a symbol have every object's methods
  ((!o).hasOwnProperty(k), a minifier's false: a component that died
  there left what followed it empty); each promise job has its own
  budget of steps (a page that renders in a thousand thens is not a
  loop that never ends: the first to pass the budget took every job
  after it); IntersectionObserverEntry is a class (without it a page
  brings its own observer, which here saw nothing) and an element of
  no height yet is seen by one pixel; a picture's height in percents
  is of its block's height when that is known, else its own ratio
  (it was 0); a line is inside what clips it down to its baseline (a
  picture filling its box has a line a little taller, and was left
  out). And a script's request body of bytes (a Uint8Array) is sent
  as bytes
- YouTube's search page shows its first results (a video's title and
  channel, drawn by YouTube's own components), two minutes and a half
  after it is asked: document.all is something (a sanitizer of
  YouTube's compares every value with it, and undefined was "it":
  every value not given was replaced by its placeholder, "zClosurez",
  which hid the results)
- YouTube's application starts: its masthead is drawn by its own
  components (Polymer), where the server's grey skeleton stayed. What
  it took, each a thing of the platform: a custom element's class
  takes its properties' assignments and answers before the browser's
  own of the same name (Polymer's el.data, this.async); new on a bound
  function; __proto__ read and set; match and search with a string
  (an expression's text); an element's attributes asked by name
  (getNamedItem); a DataView's floats; what a script puts on document
  kept; an object given where a text is expected, by its toString
  (trusted HTML). youtube.com is asked as Chrome is (Browser_agent)
- the DOM's members are on its prototypes too (Node.prototype's
  firstChild, Element.prototype's querySelector...: thin accessors
  that ask the element), for the code that takes them from there --
  Shady DOM, which YouTube runs in every browser. A property defined
  on window with a getter and a setter is set through it, one defined
  with a value is the global; new Array(3)'s places not given are
  skipped by map and forEach; CDATASection, ProcessingInstruction,
  Range, WheelEvent and fifteen other events as names. YouTube's
  application goes from its first line to building its page (1,233
  elements; it then stops in its own registry of services)
- a page's comments are in the tree its scripts see (not in the one
  styled and laid out): what an application that takes over a page
  made on a server looks for -- Lit's <!--lit-part-->, React's <!--$-->
  ("hydration"). MDN's components (Lit) start with no error.
  Html_tree.parse ~comments
- a <slot>'s assignedNodes and assignedElements; console's other
  methods (info, debug, group, table, time...)
- web APIs: a <style>'s sheet (insertRule, cssRules: how
  styled-components writes its rules) and document.styleSheets; an

- every site's scripts run, not those of a few named sites: the

  scripts=host1,host2
- github.com's scripts run by default: the server's page shows in the

** Bug fixes
- the window frozen for good, now and then, on a page of many
  scripts (GitHub: a load in fifteen; every thread asleep). The
  parser takes breaths (Js_slice: a long text read lets the window be
  drawn), and since scripts are read ahead on the pool's workers a
  worker's breath ended a slice of the window's run -- a run that was
  not its own, never stopped, and that ended unseen; the window then
  told it to go on and waited for ever. A text read aside takes no
  breath (Js_parse.parse ~aside), and continue starts nothing if
  nothing is paused. Caught by loading the page in a loop under gdb
  until it hung: the window's thread in Js_slice.wait, the scripts'
  in Js_slice.work, on the same condition
- a sticky regular expression (/y) matches at its lastIndex and moves
  it: it was read as 0 each time, and a parser written with them never
  advanced (Fluent's, on MDN: fourteen scripts stopped as "ran too
  long", 100 s of them)
- a comment's or a text's nextElementSibling and previousElementSibling
- the bytes of an array of 16 or 32 bit integers (new
  Uint8Array(hashes.buffer)): the numbers' bytes, not the numbers
- regular expressions: in a class, a range whose bounds are \u
  escapes ([\u0020-\u007e]) lost its upper bound when the expression
  was made from a string (new RegExp): the BBC's page went blank two
  loads in three, a polyfill rebuilding its expressions so
  (docs/dev/notes_debugging_techniques.txt, session 5)
- a <script>'s and a <style>'s innerHTML is their text, not markup
  ("r<t;r++" in a script written so was read as a tag)
- GitHub's tabs (Issues, Pull requests) could not be clicked: a menu
  waiting, hidden (visibility: hidden), lay over them and took the
  click -- what is not seen is no longer under the pointer; and the
  link was not found, the tab being a flex box inside its <a> -- a
  click with no link under it asks the tree for the nearest <a href>
  (Hit.enclosing_link). The pointer's events told to a page
  (mousedown...) have the element under it for target, and
  contains() of what is not a node is false
- the log's lines are made whole, then written under a lock held for
  that alone: with the pool's workers domains, one formatter was
  shared by all inside a lock an exception could leave taken (a load
  with -v stopped once, every thread asleep)
- with -v, a click says what it was on and what became of it
- parent.prepend(child) of the child already first lost it
  (example.com's own text, with its script)
- OCaml 5.5: Brotli's dictionary was embedded between {| and |}, where
  that compiler reads a carriage return and a newline as a newline
  alone: every answer in Brotli failed. Embedded escaped
- the browser no longer hangs on a page whose listener is not a
  function: the error's message showed the value whole, an
  application's every object many times over. A value is shown five
  objects deep, no further
- JavaScript, found on 9fans.topicbox.com: a function expression's
  name is the function in its body whatever it is outside (it was not
  when a name of the outside was the same: e, in a script made
  small); the second argument of forEach, map, filter, some, every,
  find and findIndex is the function's this; new Number(5) and new
  String("a") hold their value (new Number(5) + 1 called itself
  without end). An error says more: o[k] is not a function names the
  key, an expression is shown as written; JS_STACK=1 says the calls an
  overflow leaves by
- GitHub's repository page drawn as Chrome draws it with scripts off
  (docs/plans/plan_sites.md, step 1; docs/screenshots/github.png), by
  what was wrong one at a time, each on a page of ten lines first:
  a float that fits its line to the last bit of a sum was put under it
  (Notifications, Fork, Star); a flex item's max-width in percents was
  asked twice, the second time of itself; a width in percents inside
